# Instruções — Registro de Bugs Conhecidos

Base de conhecimento de bugs reais já encontrados e **como foram resolvidos ou diagnosticados** (não é tracker de
status). O arquivo começa com `.` para aparecer primeiro na listagem. Nunca apague nem renomeie.

Um arquivo por bug: `AAAA-MM-DD-slug-curto-do-bug.md` (slug em kebab-case, português, sem acento).

Estrutura:

```markdown
# Título curto e específico

**Data:** AAAA-MM-DD
**Severidade:** Crítica / Alta / Média / Baixa
**Onde:** arquivo(s) ou rota(s)
**Causa raiz:** o que realmente causava (não só o sintoma)
**Como foi descoberto:** (opcional)
**Correção:** o que foi feito
**Fonte:** sessão em docs/sessoes-claude/
```

Regras: português direto; nunca dado sensível; não reescrever registros antigos (se voltar por outro motivo, criar
um novo referenciando o antigo).
